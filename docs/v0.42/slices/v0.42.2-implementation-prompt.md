## Mandatory workflow

Before making any code change:

1. Check that all previous slice branches/PRs are merged into `main`.
2. If any previous branch or PR is unmerged, stop and report it.
3. Update local understanding from latest `main`.
4. Propose branch `v0.42.2-transport`.
5. Give a brief implementation intent and list the libcbus files/protocol references you expect to use.
6. Stop and wait for approval.

After approval, create the branch from latest `main` and implement only this slice.

## Objective

Provide reliable byte-stream access to a physical C-Bus PCI over serial and a CNI over TCP, without interpreting protocol content.

## Scope

- Serial PCI connection at the required C-Bus serial settings.
- TCP CNI connection.
- Connect, disconnect, cancellation and reconnect hooks.
- Raw byte read/write interfaces suitable for wire/framing code.
- Integration with capture/logging from v0.42.1.

## Owned areas

- `internal/transport/`

## Constraints

- No framing or packet parsing.
- No PCI initialisation sequence yet.
- No automatic reconnect policy beyond clean lifecycle primitives.

Additional constraints:

- Binary name is `GoCBus` wherever this slice touches executable naming.
- Do not introduce C-Gate as a dependency.
- Do not translate libcbus line-for-line. Preserve protocol behaviour, improve structure.
- Keep public APIs as small as practical.
- Prefer table-driven tests and captured fixtures.
- Do not begin the next slice as a "small extra".
- Update `docs/v0.42/ImplementationState.md` with actual implementation status, discoveries, deferrals and design variations before opening the PR.

## Exit criteria

- Serial and TCP transports can be opened, read, written and closed cleanly.
- Disconnects propagate clearly to the caller.
- Raw traffic can be captured without protocol knowledge.

When complete, summarise what changed, tests run, known issues, and any design variation. Then open a PR against `main`.
