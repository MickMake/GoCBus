# GoCBus v0.42.11 - Maintenance passthrough Design

## Status

**Release:** v0.42.11  
**Design status:** Planned

## Objective

Allow C-Gate/Toolkit maintenance without stopping GoCBus or swapping daemons.

## Owned areas

- `internal/passthrough/`

## Scope

- Manual passthrough mode.
- Suspend normal GoCBus C-Bus processing.
- Expose physical stream on a TCP listener.
- Single maintenance client.
- On exit reclaim, reinitialise and fully resynchronise.

## Design rules

- Where this slice migrates behaviour that already exists in libcbus, use libcbus as the primary behavioural baseline and preserve its proven observable behaviour unless a documented corrective deviation is required.
- Implementation structure should be idiomatic Go and need not resemble the Python architecture.
- Keep interfaces small and unknown protocol input observable.
- Record any material design variation or behavioural deviation from libcbus in `docs/v0.42/ImplementationState.md`.

## Deliberate non-goals

- No simultaneous GoCBus/C-Gate multiplexing.
- No full virtual CNI.
- No UDP CNI discovery unless proven necessary.

## Exit criteria

- Any behaviour migrated from libcbus has equivalent observable results except for explicitly documented corrective deviations.
- C-Gate/Toolkit can perform maintenance while GoCBus stays running.
- Normal processing is suspended during passthrough.
- Exit performs clean reinitialisation and resync.

## Exclusive handover acceptance

- On entry, stop normal command admission, settle/cancel pending work with explicit outcomes, stop the normal reader/writer, then grant one maintenance client exclusive stream ownership. No normal queued write may cross that handover.
- Mark group state stale while normal observation is suspended; keep normal Lighting commands rejected until ownership and the documented command-admission conditions are restored.
- Define and test failed listener/client setup, explicit exit, unexpected client loss and process shutdown. Each must leave one known owner or a reported unavailable interface, never competing readers/writers.
- On recovery, close maintenance access, reclaim/reinitialise the interface and resynchronise before treating old state as current. Do not replay pre-handover commands.
- Provide a minimal local entry/exit mechanism in this slice and document its use; Slice 13 adds MQTT/HA controls over the same APIs.
