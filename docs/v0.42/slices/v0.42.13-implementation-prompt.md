## Objective

Provide one authoritative runtime control/status surface and useful MQTT/HA operational controls.

## Scope

- Lifecycle states DOWN, CONNECTING, INITIALISING, SYNCING, UP, PASSTHROUGH, DEGRADED, ERROR.
- MQTT/HA status sensor.
- Passthrough, debug/raw logging, force-resync and safe reconnect controls.
- Last-message/sync timestamps and useful counters.

## Owned areas

- `internal/control/`
- `internal/runtime/`
- `internal/homeassistant/`

## Constraints

- Do not expose every internal boolean.
- Avoid contradictory flags.
- Controls use explicit APIs.
- Binary name is `GoCBus` wherever relevant.
- No C-Gate dependency.
- Use libcbus as the primary behavioural baseline for protocol behaviour in this slice.
- Preserve proven observable behaviour unless a documented corrective deviation is required.
- Do not translate Python structure line-for-line; implement the behaviour using the simplest idiomatic Go structure.
- Do not begin the next slice as a small extra.

## Exit criteria

- Behaviour migrated from libcbus has equivalent observable results except for explicitly documented corrective deviations.
- Operator can identify C-Bus lifecycle state.
- Approved HA/MQTT controls work safely.
- Transitions are logged and testable.

Update `ImplementationState.md`, run tests, summarise variations, then open a PR against `main`.
