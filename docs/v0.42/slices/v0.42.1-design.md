# GoCBus v0.42.1 - Foundation Design

## Status

**Release:** v0.42.1  
**Parent release:** v0.42  
**Design status:** Planned  
**Dependencies:** None

## Objective

Establish the smallest common protocol primitives, diagnostics conventions, and capture/replay scaffolding needed by every later slice.

## Owned areas

- `internal/capture/`
- `internal/wire/ (shared constants/helpers only)`
- `testdata/`

These directory boundaries are part of the v0.42 design. A slice may use public interfaces from earlier slices, but it should not casually move another slice's responsibility into its own package.

## Scope

- C-Bus constants and strongly typed identifiers required immediately by later slices.
- Checksum helpers and basic validation helpers.
- Raw traffic capture/replay format for deterministic tests.
- Logging conventions and levels, including raw RX/TX trace output.
- Initial Go module/package skeleton and test layout.

## Design rules

- Keep the implementation idiomatic Go rather than translating Python structure line-for-line.
- libcbus is the behavioural baseline for protocol behaviour in this slice.
- Preserve its proven observable behaviour unless a documented corrective deviation is required.
- Implementation structure should be idiomatic Go and need not resemble the Python architecture.
- Prefer explicit small types and interfaces over framework-style abstractions.
- Unknown or unsupported protocol input must remain observable.
- Tests should be deterministic and should use captured/known protocol fixtures where possible.
- Any material design variation or behavioural deviation from libcbus must be recorded in `docs/v0.42/ImplementationState.md` before the slice is considered complete.

## Deliberate non-goals

- No serial/TCP connection code.
- No packet decoding.
- No MQTT or Home Assistant code.
- Do not port all of libcbus/common.py merely because it exists.

## Exit criteria

- Behaviour migrated from libcbus has equivalent observable results except for explicitly documented corrective deviations.
- Checksum helpers are covered by table-driven tests against known libcbus examples.
- A capture file can be written and replayed as timestamped RX/TX byte records.
- Later slices can depend on stable shared types without importing application-specific packages.

## Reference material

Primary reference is Michael Farrell's `micolous/cbus` / libcbus, particularly the files relevant to this slice. Translate behaviour and protocol knowledge into Go; do not preserve Python architecture merely for familiarity.

## Completion record

When implemented, update `docs/v0.42/ImplementationState.md` with:

- completion status,
- files/packages actually created,
- tests added,
- discoveries,
- deferred issues,
- any variation from this design.
