# GoCBus v0.42.10 - Home Assistant Design

## Status

**Release:** v0.42.10  
**Design status:** Planned

## Objective

Expose GoCBus through Home Assistant's MQTT framework.

## Owned areas

- `internal/homeassistant/`

## Scope

- MQTT Discovery for Lighting.
- Brightness/transition where supported.
- Stable entity/device IDs and availability.
- Simple naming/config mapping.

## Design rules

- Where this slice migrates behaviour that already exists in libcbus, use libcbus as the primary behavioural baseline and preserve its proven observable behaviour unless a documented corrective deviation is required.
- Implementation structure should be idiomatic Go and need not resemble the Python architecture.
- Keep interfaces small and unknown protocol input observable.
- Record any material design variation or behavioural deviation from libcbus in `docs/v0.42/ImplementationState.md`.

## Deliberate non-goals

- No HA custom component.
- No duplicate state engine.
- Lighting only for v0.42.

## Exit criteria

- Any behaviour migrated from libcbus has equivalent observable results except for explicitly documented corrective deviations.
- HA discovers configured groups.
- Physical changes appear in HA.
- HA commands operate C-Bus.

## Discovery compatibility acceptance

- Resolve the Slice 9 compatibility table's discovery entries before implementation. The pinned `cmqttd.py` advertises every group, light/binary-sensor pairs and group-only IDs; do not silently inherit those defaults.
- Confirm the configured-group selection rule, binary-sensor companion policy and context-preserving stable entity/device IDs. Decide whether existing cmqttd identities need preservation; do not build migration machinery without that requirement.
- Record how unknown/stale fields and subsystem availability map to HA without manufacturing fresh brightness or a second state engine.
- Test restart/reconnect identity stability, non-collision across supported group contexts, configured discovery scope and the selected stale/unknown availability behaviour.

## Completion record

Update `ImplementationState.md` with completion, tests, discoveries, deferrals and design variations.
