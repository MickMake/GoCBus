# GoCBus v0.42.5 - Lighting receive Design

## Status

**Release:** v0.42.5  
**Parent release:** v0.42  
**Design status:** Planned  
**Dependencies:** v0.42.4

## Objective

Decode the C-Bus Lighting application into small typed Go events.

## Owned areas

- `internal/lighting/`

These responsibility boundaries are part of the v0.42 design. The exact Go package topology may be simplified where implementation evidence supports it, provided responsibilities remain clear and the variation is recorded in `ImplementationState.md`.

## Scope

- Lighting ON decode.
- Lighting OFF decode.
- Lighting RAMP decode including level and supported ramp durations.
- Terminate-ramp decode where present.
- Typed events carrying source/group/application information where available.

## Design rules

- Keep the implementation idiomatic Go rather than translating Python structure line-for-line.
- libcbus is the behavioural baseline for protocol behaviour in this slice.
- Preserve its proven observable behaviour unless a documented corrective deviation is required.
- Implementation structure should be idiomatic Go and need not resemble the Python architecture.
- Prefer explicit small types and interfaces over framework-style abstractions.
- Unknown or unsupported protocol input must remain observable.
- Tests should be deterministic and should use captured/known protocol fixtures where possible.
- Any material design variation or behavioural deviation from libcbus must be recorded in `docs/v0.42/ImplementationState.md` before the slice is considered complete.

## Deliberate non-goals

- No current-state ownership.
- No command sending.
- No MQTT publication.

## Exit criteria

- Behaviour migrated from libcbus has equivalent observable results except for explicitly documented corrective deviations.
- Known libcbus Lighting fixtures produce equivalent logical events.
- Null/odd Lighting packets observed by libcbus are handled safely.
- Lighting events are suitable inputs for a later state engine.

## Integration acceptance

- Demonstrate captured/replayed bytes producing typed Lighting events through the existing capture/decoder path.
- Self-initialising live monitoring is the Slice 6 milestone; any earlier live demonstration must record its PCI setup assumptions.

## Reference material

Primary reference is Michael Farrell's `micolous/cbus` / libcbus at pinned v0.42 commit `cc0bdf3a25bd5646dd2d8e7d88a46fcd198f53a1`, particularly the files relevant to this slice. Translate behaviour and protocol knowledge into Go; do not preserve Python architecture merely for familiarity.
