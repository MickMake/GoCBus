# GoCBus v0.42.12 - Runtime integration and configuration completion Design

## Status

**Release:** v0.42.12  
**Design status:** Planned

## Objective

Complete runtime orchestration and configuration integration around the minimal executable/configuration spine established in Slice 1.

## Owned areas

- `cmd/GoCBus/`
- `internal/runtime/`

## Scope

- Extend and consolidate the config file/CLI plumbing introduced in Slice 1 for all implemented subsystems.
- Binary name remains GoCBus.
- Foreground by default.
- SIGINT/SIGTERM clean shutdown.
- Ordered startup/shutdown across C-Bus, state and MQTT.
- Service-manager friendliness.

## Design rules

- Where this slice migrates behaviour that already exists in libcbus, use libcbus as the primary behavioural baseline and preserve its proven observable behaviour unless a documented corrective deviation is required.
- Do not replace the working Slice 1 configuration model merely to make it more general; extend it only where implemented subsystems require real settings.
- Implementation structure should be idiomatic Go and need not resemble the Python architecture.
- Keep interfaces small and unknown protocol input observable.
- Record any material design variation or behavioural deviation from libcbus in `docs/v0.42/ImplementationState.md`.

## Deliberate non-goals

- No internal service manager.
- No requirement for daemon mode.
- Service wrappers are packaging concerns.

## Exit criteria

- Any behaviour migrated from libcbus has equivalent observable results except for explicitly documented corrective deviations.
- GoCBus runs interactively with useful logs.
- Configuration validates cleanly.
- Shutdown leaves transports and MQTT known.

## Completion record

Update `ImplementationState.md` with completion, tests, discoveries, deferrals and design variations.
