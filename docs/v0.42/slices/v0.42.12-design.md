# GoCBus v0.42.12 - Runtime and configuration Design

## Status

**Release:** v0.42.12  
**Design status:** Planned

## Objective

Define how GoCBus runs and is configured, with foreground execution as the default.

## Owned areas

- `cmd/GoCBus/`
- `internal/runtime/`

## Scope

- Binary name is GoCBus.
- Foreground by default.
- Config file plus CLI overrides.
- SIGINT/SIGTERM clean shutdown.
- Ordered startup/shutdown.
- Service-manager friendliness.

## Design rules

- libcbus is the behavioural baseline for protocol behaviour in this slice.
- Preserve its proven observable behaviour unless a documented corrective deviation is required.
- Implementation structure should be idiomatic Go and need not resemble the Python architecture.
- Keep interfaces small and unknown protocol input observable.
- Record any material design variation or behavioural deviation from libcbus in `docs/v0.42/ImplementationState.md`.

## Deliberate non-goals

- No internal service manager.
- No requirement for daemon mode.
- Service wrappers are packaging concerns.

## Exit criteria

- Behaviour migrated from libcbus has equivalent observable results except for explicitly documented corrective deviations.
- GoCBus runs interactively with useful logs.
- Configuration validates cleanly.
- Shutdown leaves transports and MQTT known.

## Completion record

Update `ImplementationState.md` with completion, tests, discoveries, deferrals and design variations.
