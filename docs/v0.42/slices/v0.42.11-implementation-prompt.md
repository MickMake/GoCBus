Implement slice **v0.42.11 - Maintenance passthrough**.

## Mandatory workflow

Before code changes: verify previous slice PRs are merged to `main`; inspect latest `main`; identify the exact libcbus behaviour being migrated and the tests/fixtures that can demonstrate compatibility; propose branch `v0.42.11-maintenance-passthrough`; state intent and relevant libcbus references; then **stop for approval**. After approval branch from latest `main` and implement only this slice.

## Objective

Allow C-Gate/Toolkit maintenance without stopping GoCBus or swapping daemons.

## Scope

- Manual passthrough mode.
- Suspend normal GoCBus C-Bus processing.
- Expose physical stream on a TCP listener.
- Single maintenance client.
- On exit reclaim, reinitialise and fully resynchronise.

## Owned areas

- `internal/passthrough/`

## Constraints

- No simultaneous GoCBus/C-Gate multiplexing.
- No full virtual CNI.
- No UDP CNI discovery unless proven necessary.
- Binary name is `GoCBus` wherever relevant.
- No C-Gate dependency.
- Use libcbus as the primary behavioural baseline for protocol behaviour in this slice.
- Preserve proven observable behaviour unless a documented corrective deviation is required.
- Do not translate Python structure line-for-line; implement the behaviour using the simplest idiomatic Go structure.
- Do not begin the next slice as a small extra.

## Exit criteria

- Behaviour migrated from libcbus has equivalent observable results except for explicitly documented corrective deviations.
- C-Gate/Toolkit can perform maintenance while GoCBus stays running.
- Normal processing is suspended during passthrough.
- Exit performs clean reinitialisation and resync.

Update `ImplementationState.md`, run tests, summarise variations, then open a PR against `main`.
